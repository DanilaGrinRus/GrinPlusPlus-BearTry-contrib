`AUDIT_DELTA.{en,de,ru}.md`, 0 `TODO`; 15 карточек содержат diff (10 — реальные

понять, что и почему изменено относительно Grin++ 1.2.9, проверить каждое
изменение по коду и доказательствам и воспроизвести сборку.

## 2. Шаблон записи в `AUDIT_DELTA.md`

```
### G-31 — горизонт PIBD
- Коммит: 39b77a9
- Файлы: src/P2P/Sync/StateSyncer.cpp:162-190
- Было: horizon.BlockHash = pTip->GetHash()
- Стало: archiveHeight = (head − STATE_SYNC_THRESHOLD), округление вниз до 720;
          горизонт берётся по заголовку этой высоты
- Почему: эталон chain/src/chain.rs:985 (txhashset_archive_header)
- Доказательство: E31 (живой сегмент сходится с header.output_root), unit-тесты
- Риск: неверный горизонт → пир не отвечает; откат: вернуть tip
```

Требование: **каждый** пункт матрицы, где менялся код, получает такую запись.
Чисто документальные пункты (`DONE-R`) оформляются той же карточкой без
«было/стало».

## 3. Карта доказательств

Отдельная таблица «G-xx → тест → лог/артефакт → дата → кто проверил» с
разделением: unit / build / smoke / live / device. Пропуск и таймаут не
превращаются в PASS (правило `docs/ACCEPTANCE.md`).

## 4. Комментарии в коде — правила

1. У каждого нового файла — шапка: назначение, ссылка на Rust-эталон
   (`file:line`), ключевые инварианты.
2. Каждая константа «из эталона» — источник и формула (например,
   `TXHASHSET_ARCHIVE_INTERVAL = 12*60` → `chain/src/global.rs`).
3. Каждое отклонение от эталона — «почему» рядом с кодом и запись в
   `GAP_MATRIX`; для временных обходов — условие снятия.
4. Комментарий объясняет **почему**, а не «что»; очевидное не комментируется.
5. Отдельный проход по устаревшим комментариям (пример из практики:
   `Capabilities.h` утверждал «never advertised», когда поведение уже изменилось).
6. Критерий: аудитор, читая файл, не должен открывать Rust-исходник, чтобы
   понять смысл константы или ветки.

## 5. Что ещё проверить перед передачей

* нет секретов/ключей/адресов/seed в коде, логах и артефактах (grep-проход);
* нет отладочного кода, оставшегося от экспериментов (например, дампы сегментов
  в `MessageProcessor` — проверять `git diff` на подобное);
* сборка с чистого дерева (offline sysroot), полный прогон тестов, smoke;
* версия/UA (`GrinVersion.h` = 1.2.9) и отсутствие случайных правок baseline;
* честный список «что не проверялось».

1. После закрытия фаз 5–7 и приёмки (не раньше — иначе дельта устареет).
2. `AUDIT_DELTA.{en,de,ru}.md` дозаполнен: 26 карточек, `TODO` = 0,

## 8. Языки и глоссарий

**Требование: аудиторский пакет — на английском, немецком и русском.**
Комментарии в коде — **только на английском** (независимо от языка отчёта),
как и имена идентификаторов, сообщения коммитов и содержимое логов.

| Артефакт | Файлы | Канон |
|---|---|---|
| `AUDIT_DELTA` | `AUDIT_DELTA.en.md`, `.de.md`, `.ru.md` | EN |
| `AUDIT_COMMENTS` | `AUDIT_COMMENTS.en.md`, `.de.md`, `.ru.md` | EN |
| README пакета + чек-лист | `AUDIT_README.<lang>.md` | EN |
| Ограничения и известные проблемы | раздел в README | EN |

Правила синхронизации:

1. **EN — канонический текст**; DE и RU переводятся с него, а не друг с друга.
2. **Одинаковые якоря и ID.** Номера `G-xx`, `E-xx`, `M-01`, имена файлов,
   `file:line`, хеши и цифры не переводятся и совпадают во всех трёх версиях.
   Заголовки карточек — один и тот же шаблон, чтобы diff между языками был
   механическим.
3. **Проверка паритета** (скрипт в пакете): набор ID и заголовков в трёх файлах
   совпадает; если карточка добавлена — она есть во всех трёх, иначе пакет не
   считается готовым.
4. **Логи и evidence не переводятся** — это первичные данные; в тексте на них
   ссылаются как есть.
5. **Глоссарий** (фиксированные термины; в DE/RU — одинаковый перевод везде):

| EN | DE | RU |
|---|---|---|
| PIBD (parallel initial block download) | PIBD | PIBD |
| PIHD (parallel initial header download) | PIHD | PIHD |
| txhashset | TxHashSet | txhashset (набор состояния) |
| rangeproof | Rangeproof | rangeproof (доказательство диапазона) |
| kernel | Kernel | ядро (kernel) |
| MMR / PMMR | MMR / PMMR | MMR / PMMR |
| header head / chain head | Header-Head / Chain-Head | голова заголовков / голова цепочки |
| peer | Peer | пир |
| checkpoint | Checkpoint | чекпоинт |
| crash-consistency | Crash-Konsistenz | краш-согласованность |

6. **Комментарии в коде** — английский, кратко и по делу: инвариант, источник
   константы (Rust `file:line`), причина отклонения. Локализованные комментарии
   не допускаются: они расходятся с кодом и мешают аудиту.
7. **Ошибки/строки UI** не входят в этот пункт — у них своя i18n-политика
   продукта; в аудиторском пакете они цитируются как есть.
