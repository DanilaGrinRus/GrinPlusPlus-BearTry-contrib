# AUDIT_COMMENTS — ревизия комментариев в коде

Статус: **скелет, ревизия не выполнена.** Создан 31.10.2026 как часть
аудиторского пакета (`AUDIT_PACKAGE.md` §4, `GAP_MATRIX` G-51). Пока это план и
чек-лист; заполняется перед передачей пакета.

## 1. Правила (обязательные)

1. Комментарии в коде — **только на английском**; локализованный комментарий
   считается дефектом (расходится с кодом и мешает аудиту).
2. У каждого нового файла — шапка: назначение, ссылка на Rust-эталон
   (`file:line`), ключевые инварианты.
3. Каждая константа «из эталона» — источник и формула рядом с объявлением.
4. Каждое отклонение от эталона — «почему» и запись в `GAP_MATRIX`.
5. Временный обход — условие снятия; иначе он останется навсегда.
6. Комментарий объясняет **почему**, а не «что»; очевидное не комментируется.
7. Устаревшие утверждения («never advertised», «only once») — отдельный проход:
   они опаснее отсутствия комментария.
8. Критерий приёмки: аудитор не должен открывать Rust-исходник, чтобы понять
   смысл константы или ветки.

## 4. Чек-лист по файлу

Для каждого файла из §2 отметить:

| Поле | Что проверяется |
|---|---|
| Header | есть ли шапка с назначением и ссылкой на Rust |
| Constants | у констант указан источник (`file:line`) |
| Invariants | описаны ли состояния/инварианты (кто владеет, что нельзя) |
| Deviations | каждое отличие от Rust объяснено и есть в `GAP_MATRIX` |
| Stale | нет утверждений, которые код уже не выполняет |
| Language | комментарии только на английском |
| Debug | нет временных дампов/принтов/закомментированного кода |
