## 2. Границы

* **В задаче:** `BlockSyncer`, per-peer высота, политика ретраев/ротации,
  «медленные» пиры, seeder (лог и восстановление), watchdog статуса, наблюдаемость.
* **Вне задачи:** PIBD/desegmenter, консенсус, кошелёк, API-форматы, версия.
* Не ослаблять `/W4 /WX`; не расширять `BAN_WINDOW` глобально — вводить отдельный
  короткий cooldown «непродуктивного» пира, не трогая срочный бан за фрод.

## 3. Требуемое поведение

1. **Не банить за молчание.** Таймаут = переназначить блок другому пиру +
   счётчик; никакого `FraudHeight` по таймауту.
2. **`FraudHeight` — только доказанный фрод:** пир заявил TD/высоту выше нашего
   header head и 120 с не отдаёт заголовки (как `header_sync.rs:135-141`), либо
   прислал блок/заголовок, не соответствующий заявленному. Причина и время — в лог.
3. **Окно запросов:** `min(candidate tip, networkHeight, per-connection height)`;
   не просить у пира блоки выше его `Ping`-высоты. Батч ≤ `min(100, peers*10)`,
   ограниченное число в полёте.
4. **Ретраи по образцу Rust:** 6 с до повтора, 1 с при прогрессе, backoff,
   ротация пиров; флаг `RETRIED` не должен превращаться в бан.
5. **`m_slowPeers` → cooldown с TTL** (например 60 с) и сброс при успешном
   блоке; «медленный» не является условием бана.
6. **Seeder:** при `GetNewPeer() == nullptr` — `INFO/WARN` с причиной
   (все в бане / нет адресов / DNS пуст / `RETRY_WINDOW`), продолжать seeding
   с backoff; после успешного handshake — снимать короткий cooldown.
7. **Watchdog:** `WAITING_FOR_PEERS` логируется с причиной и попадает в
   REST-статус; сейчас это полностью молчаливое состояние.
8. **Наблюдаемость:** счётчики запросов/таймаутов/переназначений/банов по
   причинам в `/v1/status`; исходящий бан — с причиной и длительностью.
